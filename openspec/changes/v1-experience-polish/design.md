## Context

见 proposal.md 与 docs/V1_RELEASE_UPGRADE_PLAN.md。九尾狐固定为 topic_01/shanhai_01。当前测试套件暂停，使用正常窗口观察、实际状态与日志，真机体验单独记录。

## Goals / Non-Goals

**Goals:** 共用模块改善三模式质感与交互；清理失效旋转调用链；不中断现有进度。

**Non-Goals:** 不重生成全部关卡，不改变切割拓扑和玩法规则，不增加社交或难度。

## Decisions

- 先记录九尾狐实际三模式，再删除失效旋转参数和几何分支；旧状态读取忽略角度。装饰图标变换保留。
- 用独立绘制模块根据原多边形生成侧面与边缘高光；保持贴图和命中几何，避免整套 3D 迁移成本。
- 每个可中断动作持有并取消旧 Tween；跟手位置保持直接更新，视觉反馈与匹配规则分开。
- UI 复用现有场景与稳定时间轴，按游戏页、完成、模式选择顺序处理。
- 通过已有编辑器桥或正常窗口进入真实场景；不新增测试或篡改基线。外部试玩和真机不可用时保持对应任务未完成。

## Tray Interaction Design

2026-09-07 新增需求，优先于剩余 UI 收尾实施。仅 polygon、knob 使用两行托盘；swap 保留原操作。此次为计划更新，以下均为待实现，不将既有拿放修复视为满足新交互。

### Layout and compaction

- 单一有序碎片列表，按列交替分配上下行：第 0、1 块为第一列，第 2、3 块为第二列。两行共用一个横向偏移量，不分别滚动。列宽取该列两块缩放后宽度的较大值，加统一间隔；高度按行可用高度等比适配，限制极宽碎片占用，保证命中区域不跨行。
- 按用户追加要求，标准布局托盘由 400 增至 520（约占竖屏 20%），为每行增加可辨认尺寸；交换按钮区不变。九尾狐同窗口、同滚动起点对比完整可辨认碎片数；目标至少增加 50%，并保留最小 44 × 44 逻辑点的可用触控单元。此为样板验收目标，窄长轮廓另查；不靠无限缩小实现数量指标。
- 抓取期间保留原槽占位，冻结顺序，不让其他碎片在手下换位。放回托盘保持原顺序，不增加托盘排序玩法；只有确认离开托盘的碎片才从序列移除并统一压紧，两行剩余数量差不超过 1（拖动中的占位计入）。
- 补位仅在提交放下／取消后的稳定时机发生。保持最近可见且未移动碎片的屏幕横向位置作为滚动锚点；锚点被删除时使用最近保留项，末端再做边界限制，避免每次重排跳回开头。补位动画可立即被抓取打断；不把拖动浮层作为滚动锚点。
- 两行均支持少量、奇数、空托盘、极宽／细长碎片，以及恢复存档、提示定位和视口变化。行列是派生布局，不改变碎片 ID 和匹配规则；旧横向偏移越界时限制到有效范围。

### Gesture state and hysteresis

| 状态 | 碎片 | 托盘 | 退出条件 |
| --- | --- | --- | --- |
| 空闲 | 槽内显示 | 可处于松手惯性 | 按下任意碎片立即抓取；按下空白则纯滚动 |
| 抓取且允许滚动 | 同一碎片持续跟手、在浮层显示 | 手指横向位移 1:1 驱动两行 | 纵向偏移达到锁定阈值或离开托盘可交互区 |
| 抓取且锁定滚动 | 同一碎片继续二维跟手 | 横向偏移冻结、无惯性 | 回到起始高度的恢复带且指针在托盘内 |

- 记录按下瞬间的屏幕位置、局部抓取点、原槽 ID 和唯一触点。按下不等待方向决策或长按，立即停止惯性并取消被抓碎片旧回位动画。
- 初始调参建议：锁定阈值为纵向偏移绝对值 24 逻辑点，恢复阈值为 12 逻辑点，满足恢复阈值 < 锁定阈值。两阈值间保持当前状态，上下方向一致。阈值按屏幕逻辑点映射到项目坐标，不直接使用 1206 设计像素；数值需真机确认。
- “回到原位置附近”明确为回到按下时的高度带，不要求横坐标返回；否则横滑一段后很难重新浏览。手指仍在托盘外时不能恢复滚动，掠过另一行也不更换抓取对象。
- 切换时重设滚动增量基准和速度采样；锁定期间积累的横向位移不得在恢复瞬间补算，也不能带入松手惯性。全程保持一个抓取会话，不合成松手／重按，不重复播放拿起反馈。
- 托盘内松手归还原顺序槽位；允许滚动状态下可接续惯性。锁定状态下松手不启动旧滚动惯性。托盘外松手沿用当前棋盘合法放置／吸附／无效回位规则，不根据拖动速度自行放置。取消、切后台、多指接管不提交拼接、不启动惯性，并释放抓取、占位和浮层。

### Position, layering and inertia

- 被抓碎片使用不被托盘裁剪的独立浮层，始终高于两行静止碎片及其补位动画；系统模态层仍在其上方。跨行、离开和重返托盘时保持抓取点连续，不被底层滚动二次加位移。
- 拖动位置按最新输入直接计算；横向托盘滚动在触点仍按住且允许滚动时按当前位移直接计算。两者不得通过追赶 Tween、位置 lerp、弹簧或延迟队列进行平滑。缩放／提起装饰不得改变局部抓取点对应的屏幕位置；移除现有拖出偏移 Tween 对位置的影响。
- 托盘到边界时做确定性限制，首版不增加橡皮筋／边缘自动滚动。在允许范围内，内容与手指的横向位移一致；锁定是显式例外。
- 松手速度用最近约 80–120ms 的有效滚动输入估计，静止停留后松手速度应归零；避免只取最后一帧噪声。仅允许滚动状态或空白滚动释放后启动惯性。使用按 delta 时间衰减的速度，低速／到边界停止，再按下立即接管；取消与锁定都清空旧速度。
- 正常与 Reduced Motion 均保留必要直接操作和松手惯性；Reduced Motion 跳过装饰性提起／补位／回位过渡，不能导致触点位移比例变化。

### Ownership and validation

布局和滚动锚点提取到专门布局模块；抓取状态及阈值归专门手势控制器；速度采样与惯性归滚动物理模块；浮层只负责显示与坐标转换。BoardTrayController 协调这些职责，Game.gd／PuzzleBoard.gd 不增加新的业务状态机。

按布局、连续抓取、滚动物理、综合验收四个可运行步骤独立提交，每一步替换对应旧路径，不长期并存两套手势。使用现有正常窗口检查／临时运行观察，不新增测试或改基线；游戏固定内置屏。真机记录高速往返、反向、停手再放、边界锁定往返和连续取同一行的表现。输入到节点位置的诊断目标是在同一处理帧更新、有效范围内抓取点误差不超过 2 逻辑点；这不等同于端到端触控延迟，后者需真机录屏／帧时间证据，目标设备 60Hz 时帧预算为 16.7ms，不把未测量指标写成已达标。

## Button and Swap Guidance Update

- 棋盘只消费自己已捕获的指针释放；未捕获的松手交给 GUI，保证按钮完整收到按下／松开。拖动棋盘碎片后在 HUD 松手仍由棋盘收尾，不触发按钮。
- 托盘提示使用高于托盘底板和普通碎片的绝对层级，取消提示后恢复常规层级。
- 交换提示以 slot_index 的行优先顺序扫描，从第一个 correct_index 不等于 slot_index 的格子开始，提示该格的当前占用块和应处于该格的正确块。已正确格跳过，不受碎片数组顺序或置顶顺序影响；全正确时不提示，移动中不显示过时目标。提示不自动执行交换。
- 整盘左右各循环平移一列，边缘绕回另一侧；上下平移仍为一行。行列共享独立 SwapGridShift 模块，保证唯一占位、状态保存、完成判定、动画时长和 Reduced Motion 一致。
- 底部四按钮顺序为左、上、下、右，左右图案由现有上箭头旋转 -90／90 度得到，旋转视觉不旋转命中框。沿用原底部高度，保留按钮触控面积。

## Risks / Trade-offs

- 复杂边缘高光可能有锯齿 → 在实际缩放下检查，限制线宽并使用抗锯齿。
- 删除初始化参数影响调用方 → 全仓库追踪，更新调用及现有验证脚本参数，不新增断言。
- 固定样板不能覆盖所有数据 → 抽查不同轮廓和明暗关卡。
- 两行增加数量可能降低辨认率，压紧会改变空间记忆 → 对比九尾狐可见数量与触控尺寸，抓取中冻结布局、放下后按滚动锚点补位。
- 始终抓取可能让普通横滑显得像选中了某块 → 保持提起反馈克制，托盘内松手还原顺序，空白区仍可纯滚动。
- 无真机时无法确认触控和震动 → 桌面仅验证可观察行为，发布任务保持待验。

## Migration Plan

在 feat/v1-experience-polish 上按任务顺序接入。保持关卡 ID、碎片 ID 和存档版本语义，读取旧角度但不恢复旋转。各阶段保留变更前证据；异常时回退对应代码改动，避免删除用户数据。完成全部发布验收后才进入 main PR。
