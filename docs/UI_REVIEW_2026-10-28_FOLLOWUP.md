# UI、导航与连续游玩复查（2026-10-28）

本次在 `feat/home-fixed-navigation` 上继续修复。按仓库当前约定，gdunit 和 runtime-validation 测试套件暂停，**本次没有运行这些套件，也没有修改测试基线**。下文记录普通窗口诊断、截图检查与真实 Android 输入的实际结果，不代表穷尽所有设备、关卡和边缘组合。

## 已修复的问题

| 问题 | 原因与处理 |
| --- | --- |
| 模式页点击后无法返回 | 关闭信号同步重入协调器，但本地 `_closed` 尚未置位，重复关闭请求被 `_closing` 拦截。先完成标记再发信号；取消导航时恢复可交互状态。修复前同一复现停在 mode_select，修复后返回 levels。 |
| 模式没有默认选中 | 纸盒模式页重建选项后直接清空选择，绕过基类规则。恢复进行中优先、否则第一个未完成、全部完成则第一个可用模式的规则，并初始化纸盒示意。 |
| 拼图页返回箭头、按钮与间距不一致 | 返回箭头共用 NavigationGlyph；圆角、笔画、字体、内边距由 UiMetrics/CleanTheme 统一缩放；移除玩法页独立胶囊按钮覆盖和原生像素最小高度；关卡列表边距与安全区统一使用逻辑单位。 |
| 长标题过早省略或挤占空间 | 屏幕标题按字体测量缩小至 14 逻辑单位；首页、相册说明、完成页最多两行，主题卡片最多三行。相册顶部主题按钮使用返回按钮右侧完整空间。空间仍不足才省略，保留完整名称。 |
| 纸盒印刷长标题截断 | 印刷字号 80→56，必要时平衡为两行并给图片让出空间；提升标题缓存版本，避免旧缩略图继续显示旧文字。 |
| 交换模式再次恢复可能失效 | 同步重建棋盘时旧节点仅 queue_free，新节点名称被自动改为临时名字，破坏存档稳定标识。清理时先从父节点移除，再延迟释放。修复后重建、保存、返回、恢复均保持稳定标识。 |

## 页面和交互覆盖

桌面使用非 headless Godot 窗口，覆盖 320×568、360×640、390×844、768×1024；Android 实机为 720×1604。检查范围包括：首页、More 菜单、全部主题、关卡列表、模式选择、三种拼图玩法、完成页、设置、相册、主题选择与作品查看。截图用于检查文字、对齐、遮挡和留白，运行状态与日志用于判断流程是否完成。

- 连续切换模式 24 次后点击返回：修复前停留模式页，修复后返回关卡列表；最终 APK 又进行连续切换和返回检查。
- 普通动画和减少动态效果分别覆盖三种模式的进入、返回、重新进入、完成、确认及下一关；下一关进入目标关卡。
- 边缘短拖取消与长拖提交、取消关闭后继续操作、设置反复开关：结束后没有残留输入锁。
- 每种动态效果设置下各进行 6 次开始后快速返回检查：入场锁定期间请求可能被忽略，转场结束后的返回正常，没有永久锁定。
- 交换模式上移再下移、下移再上移使用真实按钮输入核对，排列恢复一致；三种模式的保存/恢复检查核对了棋盘状态。
- 实机最终版本覆盖后台切换再恢复、减少动态效果下的游玩按钮、模式切换、长标题、全部主题翻页、相册与作品返回。减少动态效果检查后恢复原来的关闭设置。
- 实机交换模式移动后退出再进入，对比棋盘区域截图，排列保持一致；RGB 平均差小于 0.1/255，未将抗锯齿微差宣称为逐像素完全相同。
- 普通窗口运行及最终 Android 日志未发现 SCRIPT ERROR、ERROR 或 FATAL EXCEPTION。

### 诊断边界

普通动画下，三个模式的现有棋盘交互 smoke helper 都返回 `ok: true`。减少动态效果下，该旧 helper 的拾取/托盘尺寸或交换行移动/完成时序子项出现失败，因此没有将其汇总为全绿；另用实际按钮、最终棋盘排列和完成路由核对了相关行为。

多边形与凹凸恢复的旧快照 helper 将托盘像素滚动位置计入恢复断言，而当前 session v1 持久化的是拼块/组、托盘顺序等，并不保存托盘滚动位置。因此其汇总为 false，其他状态项目一致；未擅自扩展存档协议或把该结果写成全部通过。交换模式恢复则在稳定标识修复后返回 `ok: true`。

以上是临时运行诊断，不是恢复了暂停中的回归套件。没有测试所有主题的每一个关卡，也没有穷尽多指竞争、所有 Android 导航模式、所有设备温控和系统杀进程时机。

## Android 连续游玩记录

第一版修复 APK 进行了连续 **1,807.94 秒（30 分 8 秒）** 的真实 ADB 触控运行：30 轮循环切换多边形、凹凸、交换，累计 1,405 次拖动，另包含托盘滑动、提示和页面点击。每轮记录入口/操作后截图、内存和 SurfaceFlinger 帧统计，应用 PID 全程保持不变。这是重复输入的稳定性检查，不是人工逐关通关测试。

| 指标 | 结果 |
| --- | --- |
| PSS，30 个采样 | 487.76–496.22 MiB；首样 491.21，末样 493.34 MiB，没有单调持续增长 |
| 游戏 SurfaceView 呈现间隔，首末样本差值 | 104,590 个间隔，其中 16–17 ms 占 99.42% |
| 呈现间隔分位数 | p95 落在 16 ms 桶，p99 落在 17 ms 桶；这是分桶统计，不是精确帧耗时 |
| 较长间隔 | >32 ms 占 0.49%，>50 ms 占 0.044%；包含切页、加载及采样期间 |
| 崩溃/脚本错误 | 同一进程完成全程；采集日志中未发现相关错误 |

帧统计使用游戏原生 SurfaceView 的 SurfaceFlinger 数据，首末差值不包含第一个采样前的约一分钟；没有把 Android View 的 gfxinfo 当作 Godot 渲染性能。手机通过 USB 连接，本次不能用于估算续航。

**版本边界：30 分钟运行使用第一版修复 APK。** 期间完成了最后的样式收尾和稳定存档标识修复，随后导出并安装最终 APK，做了上述短程实机回归；最终 APK 本身没有再运行完整 30 分钟。

## 后续修复：重复进入关卡列表时的盒子显示

当前实际使用的是 PagedLevelShelf，卡片同步创建；VirtualLevelGrid 的分帧创建不在此路径上。问题是卡片先等待原图加载，再通过延迟回调取得已经缓存的成品盒子。现在先同步查询完整缓存键，命中时在创建卡片的同一帧赋图，跳过原图加载；未命中仍走原有异步渲染。缓存容量保持 24，标题、进度、解锁状态与印刷版本继续参与失效判断。

非 headless 窗口诊断覆盖 A→A→B→A→B、翻页再返回：两个主题首次各生成 8 个盒子，三次热进入新增任务均为 0，首屏四张卡片在 card_visible 通知时已有盒子图片。另创建全新卡片，确认缓存命中后图片立即可用、原图纹理为空且没有创建原图加载器；修改标题后查询旧缓存未命中。进程退出 0，最终结果 `ok: true`，无脚本错误。原始记录为本地 `.artifacts/ui-audit/box-cache-flow.log`。

更新 Android APK 后，在两个主题各重复进入三次，并执行列表左右翻页、打开模式页和返回；检查图片内容及交互正常，应用日志无脚本错误或崩溃。静态检查通过，暂停中的测试套件仍未运行。本修复没有加入磁盘缓存，重启或超过缓存容量后的首次生成仍会发生。
