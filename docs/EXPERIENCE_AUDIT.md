## 修复的可复现问题

- `NaturalScrollContainer` 原先逐次取整会丢失慢拖的小数位移，边界反向还可能重复消耗位移。现在累积小数余量，并先消耗边界拉伸再移动列表。
- 滚动时第二根手指可能接管，取消触摸会产生惯性，切后台会残留按住状态。现在保持首个指针的所有权，并在取消与失焦时结束手势。
- 真机上，按住停止惯性后取消触摸，合成的鼠标松手可能误开卡片。现在停止惯性时就消费手势，取消卡片待完成的按压，并在释放后恢复交互；连续手势不会被上次延迟恢复提前解锁。
- 首页取消主题拖动原先可能提交切换。现在取消回到当前主题，切后台时清理手势。
- 交换释放原先使用最后一次移动的位置。`BoardInputController` 现在先更新释放位置，再处理交换；正常窗口验证覆盖没有中间移动事件的释放。手机实际通关使用原生 DOWN / MOVE / UP 轨迹。
- 游戏页面动画仍在运行时，棋盘原先可能接受按下。现在由导航锁和游戏页准备状态共同决定是否接收棋盘输入。
- 真机的凹凸底部一排存在不可到达的吸附位置：固定上移量会使目标手指位置落回托盘，再取消上移。`TrayDragClearance` 现在在托盘上边缘附近平滑减小上移量，继续使用原来的连续阻尼动画与出入阈值；五个底部碎片均通过实际抓取、预览和松手吸附。
- 视觉检查发现，棋盘与托盘的高 Z 值会盖住完成页，露出接缝、棋盘和托盘面板。`Game.tscn` 的 `ModalHost` 现在使用高于游戏 UI 的独立 `CanvasLayer`，保持原节点路径；完成、暂停、设置与模式选择都在正确的层上显示。完成页实际截图已确认只有名字、缩小后的完整图片和“完成”按钮。
- 暂停按钮自动获得焦点时继承了旧主题的浅色文字，和浅绿背景对比不足。共用按钮样式现在包含墨绿色的焦点文字，暂停的两个动作均采用这套字体颜色；真机已确认可读。

行为仍由滚动、主题拖动、棋盘输入、导航和托盘偏移模块分别负责。未增加 `Game.gd` 或 `PuzzleBoard.gd` 的职责。
