# JigCat 首版体验改造计划

日期：2026-09-07
状态：计划已整理；实施尚未开始。竞品证据来自在线页面，未下载实玩。

## 1. 目标与已确定范围

首版目标：保留游戏现有特色，让玩家能清楚选择玩法，舒服地操作具有实体质感的碎片，完成并欣赏作品，然后自然进入下一关。

以下为用户已确定的约束，后续实现不得自行缩减：

- 保留多边形、经典凹凸、方格交换三种核心玩法。
- 保留模式选择。三种模式平等呈现，不解释成三个难度档位。
- 不提供难度选择，每关每种模式使用既定配置。
- 旋转在产品体验中已经移除；本次要清理残留逻辑，不是再做一个关闭开关。
- 首版不做社交、排行榜、每日挑战。
- 以一个代表关卡打磨三种模式的共用实现，改进应用到所有使用该实现的关卡，不安排逐关视觉重做。
- 保留必要的进度保存、继续、重玩、提示、设置与完成流程。

主流程：主题／选图 → 模式选择 → 开始或继续 → 拼图 → 完整作品展示 → 下一关或返回。

本计划不增加关卡数量限制，不要求重制全部关卡，不引入新的玩法或完整 3D 引擎迁移。首发平台、地区、收费方式与目标设备在实施起步时明确；这些不阻塞样板关工作。

## 2. 当前实现依据与验证边界

本轮已阅读相关代码；以下是静态线索，不是已确认的真机缺陷：

| 范围 | 当前线索 | 改造意义 |
| --- | --- | --- |
| 碎片 | `PieceVisualFactory.gd` 使用 Polygon2D 贴图、均匀浅色覆盖、切线与提起阴影 | 优先验证厚度、倒角、切缝，不能只继续叠加阴影 |
| 托盘拖出 | `BoardTrayController.gd` 包含手势方向判定、坐标与缩放切换、拖动偏移 Tween | 重点检查拿起跳位、手指遮挡、滚动误判 |
| 吸附 | `BoardSnapController.gd` 在预览时修正位置，匹配后归位 | 检查是否抢手、吸附边界是否反复进入退出 |
| 方格交换 | `BoardSwapController.gd` 有独立的拖动、目标预览与回位路径 | 共用质感与时序规范，交换行为仍须独立验收 |
| 旋转 | `PuzzleBoard.gd` 仍有开关、参数、容差与转发方法；输入控制器仍有双击旋转分支 | 删除整条失效功能链，避免仅隐藏入口 |
| 状态与几何 | `BoardStateController.gd` 仍输出 rotation；`SnapSolver.gd` 仍按旋转计算 | 清理时检查旧存档、调用者和坐标语义 |

用户已指定样板：山海经「九尾狐」，`levels/topic_01/shanhai_01/level.json`。2026-09-07 已在真实游戏打开 polygon、knob、swap 三模式并保存改造前画面；后两种模式使用现有自动构建路径。后续以此关卡调节共用实现，不按其 ID 硬编码。

## 3. App Store 竞品调研与吸纳决策

调研日期：2026-09-07。主要使用美区 App Store 页面，不代表中国区可下载情况。下面区分商店描述、个别玩家评论与我们的设计推导；没有测量竞品的触控延迟、震动强度或动画时长，也未完成截图逐屏视觉评审。评分、下载量与宣传中的“顺滑”不作为品质证明。

### 3.1 重点参考对象

| 游戏与证据 | 值得参考的方向 | 转成我们的工作 | 不进入本次范围 |
| --- | --- | --- | --- |
| [Tap Color Jigsaw](https://apps.apple.com/us/app/tap-color-jigsaw/id6448845583)：商店描述明确强调不规则实木拼片、3D 视角、声音与震动 | 与“碎纸感”问题最接近，适合优先实玩比较材质与拿放反馈 | 制作具有侧边厚度、统一光照与短促落位反馈的样板；先在现有 2D 路径实现 | 不照搬数字填图、订阅体系，不据此决定迁移完整 3D |
| [Art of Fauna](https://apps.apple.com/us/app/art-of-fauna-cozy-puzzles/id1630468596)：围绕自然历史插画组织内容，提供图像与文字两种拼图路径及可访问性选项 | 同一作品支撑不同玩法；内容本身可以承担产品辨识度 | 同一张作品配三个清楚的模式入口；完成后留出作品欣赏空间；延续既有 Reduced Motion | 不增加文字拼图、百科系统或庞大定制面板 |
| [Jigsort Puzzles](https://apps.apple.com/us/app/jigsort-puzzles/id1660835173)：商店强调图块匹配还原图片；展示评论中有玩家喜欢逐步辨认完整图像，也有玩家希望知道作品地点 | 适合作为方格模式及完成后作品价值的参考 | 方格交换目标、互换过程、回位状态单独打磨；完成页优先展示已有作品名称 | 不复制每日挑战、装饰解锁和额外收集系统 |
| [Jigsawscapes](https://apps.apple.com/us/app/jigsawscapes-jigsaw-puzzles/id1589762792)：商店列出缩放、背景与已完成作品管理；展示评论有参考图遮挡棋盘、广告打断声音的抱怨 | 操作空间与连续体验是明确的检查点 | 参考图不持续挡住主要操作区；背景衬托碎片；完成演出与声音不打断下一步操作 | 不引入排行榜、活动、难度及旋转，不增加背景商店 |

评论只作为问题发现线索，不据少数评论推断所有玩家或竞品当前版本都存在同样问题。上述具体改造是我们的推导，不声称竞品已经按相同方式实现。

### 3.2 吸纳优先级

1. 立即纳入：实体拼片质感、干净操作区、清晰动作反馈、完整作品展示。
2. 低成本纳入：模式图示加一句玩法说明、作品已有名称、恢复上次模式与进度的清楚入口。
3. 首版后评估：扩展作品资料、自定义环境、大规模收藏展示。

不新增每日挑战、排行榜或社交功能；竞品拥有这些功能不构成采用理由。

### 3.3 开始调参前的短时实玩任务

优先对比 Tap Color Jigsaw 和 Jigsort，再查看 Art of Fauna 的选图与完成呈现。每款约 15–20 分钟，使用同一部目标手机，记录：

- 拿起前后的尺寸、手指与图块相对位置、目标是否被遮挡。
- 拖得很慢、突然转向、快速松手时的反应。
- 错误放置如何恢复，正确放置的视觉、声音、震动如何配合。
- 完成作品能看多久，何时能点击下一步，是否有强制等待。

产出最多一页对比记录，选取少数可复用原则；不进行无期限竞品搜集，不购买或订阅作为本计划前提。

## 4. 实施阶段与交付物

以下为专注投入的初始预算，共约 12–18 个工作日，不含商店审核与等待外部反馈。完成样板后重新估时；三种模式的完成标准不因赶进度而删除。

### P0：锁定样板与记录现状（0.5–1 天）

- [ ] 确认一个关卡在三种模式下都走真实运行路径；固定关卡 ID、布局与可复现场景。
- [ ] 记录小屏手机、主要目标手机和 iPad（若首发支持）的初始画面与主要操作。
- [ ] 每种模式记录最影响体验的三个问题，按实际现象描述。
- [ ] 明确首发设备范围和期望帧率，固定后续性能对比条件。
- [ ] 完成上述短时竞品实玩；如设备或地区不允许，标为未验证，继续自身样板。

交付物：同一关卡的三模式改造前证据、问题列表、设备与场景记录。

### P1：清理旋转残留（1–2 天）

- [ ] 追踪运行时、数据生成、存档、调试命令、教程、文案和现有测试中的旋转引用及调用者。
- [ ] 清理 `randomize_piece_rotation`、初始化参数、随机角度生成、`_rotate_group()` 入口与 Tween。
- [ ] 清理鼠标双击与触屏双击的旋转分支；保留有用的空白处视图复位语义。
- [ ] 在确认拼片不再旋转的前提下，简化吸附角度容差和相关几何计算。
- [ ] 明确旧存档读取策略：若存在历史角度数据，读取时兼容并归一到不旋转状态，避免丢失进度；新状态不再输出失效字段。必要兼容逻辑集中保留并解释原因。
- [ ] 清理文档与调试入口的过时承诺。不要按 `rotation` 关键词批量删除装饰动画、通用变换或第三方代码。
- [ ] 三模式重新进入、保存、恢复、完成；确认相邻匹配与交换行为不受影响。

交付物：失效功能链清理结果、必要兼容项说明、运行验证记录。完成标准是无可触发的游戏旋转路径，而不是全仓库不存在 rotation 字符串。

### P2：三模式碎片材质样板（3–4 天）

默认视觉方向：暖色手作环境中的哑光彩绘实体拼片。优先尝试薄实木侧边；具体厚度与光照通过运行样板确定。

- [ ] 用侧边厚度、克制倒角和统一方向的内部明暗建立实体感。
- [ ] 保留插画颜色，避免大面积泛白高光、粗黑切缝和多重描边。
- [ ] 多边形与凹凸边界保持原有拼接几何；不要为视觉圆角制造缺口或改变匹配关系。
- [ ] 方格交换使用同一材质语言；格间距、目标高亮和互换可读性独立调整。
- [ ] 静止、拿起、拖动、落位、拼合、完成六种状态一致；提起时变化克制。
- [ ] 图像明暗、缩放变化时，倒角与边线保持合适的屏幕尺寸。
- [ ] 新增职责放入专门的材质／视觉模块，避免堆入 `Game.gd`、`PuzzleBoard.gd`。

遵循资产规范：若确需生成图，源图留在运行目录外，纯色底后处理并验证 alpha；不生成烘焙投影。新增运行时阴影只在视觉方案明确需要时采用。材质优先由几何和可复用绘制实现，不逐关生成特效图。

交付物：同一关卡三模式可运行材质样板与前后对比。最多两轮集中视觉调整，每轮明确解决三个问题，再冻结材质方向。

### P3：操作与反馈（3–4 天）

共用标准：拖动位置直接跟随手指，缓动服务于提起、落位、回弹；不中断玩家下一次操作。

- [ ] 托盘横滑与拖出判定稳定，边界往返没有突然跳位或反复缩放。
- [ ] 小碎片能选中；重叠时选择规则清楚；不以放大命中区引入大量误选。
- [ ] 拼接模式调整吸附预览、进入／退出阈值与落位过渡，避免在边界抖动或抢手。
- [ ] 方格模式调整目标选择、两块互换、无效松手回位；若有行交换，也覆盖其实际路径。
- [ ] 快速连拖、松手再拿起、拖动途中返回、切后台、多指接管后状态一致。
- [ ] 集中管理动作时序，旧 Tween 可中断并清理；Reduced Motion 直接到正确终态。
- [ ] 在动作稳定后统一音效与震动；同一次成功不重复触发，设置关闭后确实静音／停震。
- [ ] 同设备记录帧时间和触控表现；先定位性能瓶颈，再决定输入、缓存或绘制优化。

交付物：三模式操作对比录像、具体问题关闭记录、性能基线与变更后数据。

### P4：UI 与完整流程统一（2–3 天）

顺序：游戏页 → 完成页 → 模式选择 → 关卡页／首页。

- [ ] 游戏页保证棋盘、托盘和工具区清楚分离；参考图可快速查看和收起，不长期遮挡。
- [ ] 完成后先清楚展示作品，再出现可及时操作的按钮；保留欣赏空间，不强制等待长演出。
- [ ] 三模式入口都有易辨认图示和一句说明；不使用难度星级区分玩法。
- [ ] 各模式未开始、进行中、已完成的状态准确，继续游戏不会误开其他模式。
- [ ] 首页与关卡页统一按钮、字体、色彩和留白，复用现有合适资产。
- [ ] 记住模式的便捷行为不得覆盖玩家明确选择；跨关继续规则在 UI 中保持可预期。

交付物：从选图、选模式、恢复到完成的完整三模式流程；更新 `UI_VISUAL_STYLE.md` 记录最终规范。

### P5：共用改动验证与发布候选（2–4 天）

“一个关卡打磨、所有关卡受益”的实现约束：样板关仅作为数据输入，不按其 ID、颜色、尺寸硬编码。统一修改绘制、布局与操作模块。若必须调整切割生成规则，先确认重新导出对碎片 ID 和存档的影响，不静默重制全部关卡。

- [ ] 抽查其他关卡的深／浅图、宽／高轮廓、细长边界、较多碎片；三模式各有覆盖。
- [ ] 检查所有首发目录项的资源和模式数据有效性；共用代码通过不代表每份数据都必然有效。
- [ ] 发现数据异常时记录个例并修正，不把抽查扩大为逐关美术重做。
- [ ] 5 位未接触项目的玩家试玩，确保三模式都有至少两人体验；记录第一次操作、误判与完成情况。
- [ ] 安装包验证冷启动、保存恢复、前后台切换、连续约 20 分钟游玩。
- [ ] 根据实际发行范围准备商店图标、真实游戏截图、简介、内容与隐私资料；发布要求以届时目标商店官方说明为准。

交付物：发布候选包、三模式验收记录、共用效果抽查记录、剩余问题清单。

## 5. 验收矩阵与停止条件

| 验收面 | 多边形 | 经典凹凸 | 方格交换 |
| --- | --- | --- | --- |
| 基础动作 | 拿起、拖动、吸附、回托盘 | 拿起、拖动、凹凸边缘匹配、回托盘 | 拿起、目标预览、互换、回位；现有行操作 |
| 材质 | 尖角、复杂外轮廓、拼合接缝 | 凹槽与凸起、接缝厚度 | 网格边界、交换时层级 |
| 连续操作 | 快速拖放与中断 | 快速拖放与中断 | 动画中重入与连续交换 |
| 状态 | 保存、恢复、重玩、完成 | 保存、恢复、重玩、完成 | 保存、恢复、重玩、完成 |
| 共用 UI | 模式状态、提示、返回、设置、完成展示 | 同左 | 同左 |

首版必须达到：

- 三种模式全部可进入、可完成；模式选择状态与存档一致。
- 旋转功能残留已清理，必要旧存档兼容有明确说明。
- 手机正常尺寸能辨认拼片厚度；细缝不吞掉插画，完成作品清晰。
- 连续操作无明显跳位、卡死、错误吸附、交换错位或输入丢失。
- 新玩家可在轻量引导后独立操作；试玩中至少 4/5 人完成首次体验关，三模式没有反复出现的阻塞点。该小样本仅作可用性门槛，不推断留存。
- 目标设备达到 P0 确定的性能预算；连续游玩无持续退化、崩溃或进度损坏。
- 其他关卡抽查证明共用改动生效，无样板专用分支。
- 首发路径无占位入口或半成品流程。

首版阻塞问题：崩溃、丢档、不可完成、重复误操作、主要设备布局错误、持续性能问题、明显材质破损。轻微审美偏好、更多皮肤和额外功能进入后续清单，不无限推迟上线。

## 6. 验证与 Git 交付约束

当前 `AGENTS.md` 明确暂停测试套件。本轮仅创建计划，没有运行游戏或测试套件；后续交付也必须明确列出实际执行与未执行的检查，不能将跳过测试的 CI 绿灯描述为测试通过。

- UI 验证按当前仓库要求在正常非 headless 窗口运行并检查；触控与震动必须真机验证。
- 不自动创建新测试或修改视觉基线；使用现有验证能力前先从当前 checkout 发现并检查。套件恢复后再按届时规则执行，不在本任务中擅自开启。
- 实现变更运行适当的现有静态检查；保存日志、设备信息和实际运行结果。截图说明外观，不独立证明状态正确或操作顺滑。
- 实施前确认活动功能集成分支；若没有，则从 main 创建 `feat/v1-experience-polish`。实现分支／PR 指向该集成分支。
- 每个阶段接入真实运行路径并替换旧路径后交付，未完成内容留在集成分支。
- 功能完整且验收完成后才发起集成分支到 main 的最终 PR，按仓库规则关联实际 Linear 标识并记录验证；不直接 push main。

## 7. 起步顺序

先选定同一关卡的三模式基线，随后清理旋转残留，再制作材质与操作样板。样板满意后把共用规范应用到 UI 并抽查其他关卡。下一项具体工作是 P0，而不是重新设计整个首页或逐关重做素材。
